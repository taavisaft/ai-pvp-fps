# Game inspection and first performance improvement — 2026-09-05

Built both client and dedicated server on macOS, ran the bog and forest reference views, and inspected framebuffer captures at 2560×1440. Existing material, renderer, and ground-texture edits were preserved.

## What changed

- Text uploads orphan the old OpenGL buffer storage before replacing vertices, avoiding waits on preceding text draws. Same font, geometry, draw order, and GL 3.3 API ceiling; no new application heap allocations in the loop. This follows [Khronos buffer-streaming guidance](https://wikis.khronos.org/opengl/Buffer_Object_Streaming).
- FPS is the reciprocal of the smoothed frame duration, rather than an average of instantaneous reciprocal durations. The old display could show 555 FPS beside an 18 ms frame time.
- Benchmarks record uncapped wall-clock frame durations. The simulation retains its existing 50 ms timestep cap.
- Skipped render passes clear their raw timing; benchmark pass labels identify CPU submission/wait time, not GPU execution time.
- Automated reference captures and benchmarks pin camera position, aim, FOV, recoil, and first-person view. Ordinary reference-view launches remain controllable.
- The offline status message no longer overlaps the performance overlay.

## Controlled comparison

Same current source and assets, with only the old versus new font uploader changed between binaries. Both variants included the corrected timing and reference-camera code. Default existing CMake configuration (no build type/optimization flags), medium quality, VSync off, 2560×1440 drawable. Forest reference; 300 warmup frames and 600 measured frames, run sequentially on the same Mac.

| Measurement | Original uploader | Updated uploader |
| --- | ---: | ---: |
| Mean frame | 14.33 ms | 6.00 ms |
| Median frame | 13.76 ms | 5.67 ms |
| 95th percentile | 17.46 ms | 7.78 ms |
| Maximum in sample | 19.95 ms | 12.55 ms |
| HUD CPU submission/wait | 7.73 ms | 0.09 ms |
| World CPU submission/wait | 4.78 ms | 4.69 ms |

Identical final instance counts: 6 LOD0 trees, 954 LOD1 trees, 18,099 impostors, 71 bushes. Mean frame duration improved about 58%. This is a short local scene comparison, not a cross-platform, GPU-time, or 16-player performance guarantee. Earlier exploratory runs had differing camera views and are excluded. Another exploratory run recorded a 66.90 ms hitch; sustained frame pacing still needs measurement.

Validation: both binaries build, diff whitespace check passes, final forest capture has intact text and no status-overlay overlap. The client also connected to the already-running local server and received world state with 100 ms simulated one-way lag, ±20 ms jitter, and 5% loss. That was a join/render smoke test, not a combat or load test. Test clients exited automatically; the existing server was left running.

A texture-unit warning appeared in both original and updated launches; it remains unresolved.

## Next priorities

1. **Online movement correctness:** current reconciliation replaces predicted position with server position and smooths the error. Add server input acknowledgments and replay of outstanding fixed-tick inputs, with repeatable movement tests under latency/loss before expanding combat complexity.
2. **Forest as usable cover:** bullets currently sweep boxes, terrain, and players but ignore tree trunks. Add shared, spatially filtered trunk sweeps that match visible trunk dimensions; prove near misses, high-speed hits, and players shielded by trunks. Keep foliage separate from solid wood.
3. **One convincing visual area:** work on a small forest edge with varied ground materials, understory, rocks, and a better weapon/hand silhouette. The inspected scenes show conspicuous ground repetition, repeated trees, broad empty slopes, and a blocky first-person weapon. Measure each addition using the same fixed views before spreading it across the map.
4. **Performance gates:** measure optimized Release builds, GPU pass timings, and sustained server ticks with 16 clients. Validate the largest state packet against the chosen UDP payload budget. Retain frame-time percentiles rather than optimizing the displayed FPS alone.
